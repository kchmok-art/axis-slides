13개 세부 단계가 이 6개 구간에 담긴다. 단계를 합치거나 병행할 수 있다. 테스트는 9단계만의 일이 아니다.

기획 단계 · 01–02

만들기 전에 먼저 정하는 것

코드를 열기 전에 "왜, 무엇을, 어디까지" 를 정해야 한다.

01 · 목적 정하기

누가, 왜 쓰는 사이트인가

  • 타깃 사용자와 해결할 문제
  • 사이트가 만든 뒤 무엇이 달라지는가
  • 성공을 판단할 기준

결과물: 목표·사용자 정의서

02 · 기능 정하기

무엇을 만들고 어디까지 만드나

  • 기능 목록과 우선순위
  • 첫 공개에 포함할 MVP 범위
  • 기능별 완료 기준

결과물: 요구사항 목록·MVP 범위

AI 동아리 예시: 첫 버전에는 로그인·공지·프로그램 신청만 넣고 사례 공유는 후속 버전으로 계획한다.

설계 단계 · 03–05

코딩 전에 구조를 그린다

03
메뉴와 이용 순서 정하기 정보구조(IA), 페이지 계층, 사용자 흐름, 접근 권한 정의
사이트맵·흐름도
04
화면 설계하기 와이어프레임, UI 시안, 디자인 시스템, 반응형·인터랙션 프로토타입
화면 시안·디자인 규칙
05
내부 구조 설계하기 기술 스택, DB 스키마, API 계약, 인증·인가 구조, 외부 서비스 연동
구조 설계서·API 명세
설계는 코드를 열기 전 가장 중요한 단계다. 여기서 바꾸면 1시간, 개발 중에 바꾸면 1일이 걸린다.

개발 단계 · 06–08

환경 준비 → 화면 → 기능

06
개발 환경 준비하기 저장소 초기화, 의존성, 환경변수, 개발·운영 설정 분리
실행 가능한 환경
07
보이는 화면 만들기 — Frontend 컴포넌트, 라우팅, 상태 관리, 반응형 UI, API 호출, 오류 상태 처리
프론트엔드 코드
08
실제 처리 기능 만들기 — Backend API, 비즈니스 로직, DB 저장·조회, 인증·인가, 오류 처리
백엔드 코드·DB·API
07·08은 병행 가능하다. 요청·응답 형식(API 계약)을 먼저 정하면 동시에 개발할 수 있다.

핵심 개념 · 화면·처리·저장

프론트엔드 · 백엔드 · 데이터베이스

신청 버튼을 누르면 세 역할이 이렇게 연결된다.

01 · FRONTEND

프론트엔드

사용자가 보고 조작하는 부분. 목록과 입력창을 보여주고, 버튼을 누르면 요청을 전달한다.

신청 버튼 → 신청 요청 전달 →
02 · BACKEND

백엔드

요청을 받아 처리하는 부분. 로그인·권한·정원 같은 업무 규칙을 확인한다.

신청 가능 여부 확인 → 저장 →
03 · DATABASE

데이터베이스

정보를 보관하는 곳. 회원·프로그램·신청 내역을 저장하고 조회한다.

신청 내역 저장 → 결과 반환
API = 화면과 처리 기능이 요청·응답을 주고받는 약속. 이 약속이 먼저 정해지면 07·08을 병행할 수 있다.

검증·빌드 단계 · 09–11

동작 확인 → 빌드 → 다시 확인

09
연결하고 테스트하기 단위·통합·E2E 테스트, 보안·성능·접근성, 실패·예외 상황 확인
테스트 결과
10
운영용 빌드 만들기 컴파일·번들링·최적화 → dist/ 또는 build/ 폴더에 산출물 생성
빌드 산출물
11
빌드 결과 검증하기 Staging에서 스모크 테스트, 핵심 경로·환경 설정 확인
배포 전 검증 결과
빌드 성공 ≠ 기능 검증 완료. 빌드는 파일을 만든 것. 기능이 되는지는 11단계에서 따로 확인한다.

배포·운영 단계 · 12–13

공개 → 모니터링 → 개선의 반복

12 · 인터넷에 공개하기

Deployment · Release · Runtime

  • 운영 환경에 결과물·설정 적용
  • 도메인·HTTPS·서버 실행 확인
  • 실제 주소에서 핵심 기능 점검

결과물: 접속 가능한 서비스·배포 기록

13 · 운영하고 개선하기

Operations · Maintenance · Iteration

  • 로그·지표 모니터링, 장애 대응
  • 백업·복구, 보안 업데이트
  • 사용자 피드백 → 다음 개발 반영

결과물: 운영 기록·개선 계획

배포 후가 끝이 아니다. 사용자 반응을 보고 다시 기획·설계·개발로 돌아가는 것이 진짜 운영이다.

기억할 것 01

개발은 6단계 13개 순서로 흐른다.
각 단계에는 만들어야 할 결과물이 있다.

기억할 것 02

빌드·배포·실행은 다르다.
빌드 성공 ≠ 기능 검증 완료.

기억할 것 03

프론트·백엔드·DB는 역할이 다르다.
API가 이 셋을 연결하는 약속이다.

기억할 것 04

기능 목록·화면 시안·데이터 구조·
개발 계획, 이 다섯 가지로 시작한다.
