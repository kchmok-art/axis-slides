07 · 핵심 개념

프론트엔드 · 백엔드 · DB

01 · FRONTEND

사용자가 보고 조작하는 화면. 버튼을 누르면 요청을 전달한다.

신청 버튼 → 신청 요청 전달 →
02 · BACKEND

백엔드

요청을 받아 처리. 로그인·권한·정원 같은 업무 규칙을 확인한다.

신청 가능 여부 확인 → DB 저장 →
03 · DATABASE

데이터베이스

정보를 보관하는 곳. 회원·프로그램·신청 내역 저장·조회.

신청 내역 저장 → 결과 반환
API = 화면과 처리 기능이 요청·응답을 주고받는 약속.

12 · 정리

순서를 알면
막히는 곳이 보인다

기억할 것 01

개발은 6단계 13개 순서로 흐른다. 각 단계에는 결과물이 있다.

기억할 것 02

빌드·배포·실행은 다르다. 빌드 성공 ≠ 기능 검증 완료.

기억할 것 03

프론트·백엔드·DB는 역할이 다르다. API가 이 셋을 연결한다.

기억할 것 04

기능 목록·화면 시안·데이터 구조·개발 계획 다섯 가지로 시작한다.

처음 만드는 것도, AI로 빠르게 만드는 것도 — 순서는 같다.
