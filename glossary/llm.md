### RAG

`LLM` · Retrieval-Augmented Generation · 추가 2026-10-05

**정의** LLM이 답하기 전에 외부 문서를 검색해서 그 내용을 바탕으로 답을 생성하는 방식.

**자세히**

RAG = 검색(Retrieval) + 보강(Augmented) + 생성(Generation) 3단계 구조.  
- ① 검색: 질문과 관련된 문서·데이터를 벡터DB 등에서 찾아온다.
- ② 보강: 찾아온 문서를 컨텍스트에 함께 넣는다.
- ③ 생성: LLM이 그 문서를 참고해서 답을 만든다.

RAG가 필요한 이유 3가지:  
- 1. 할루시네이션 방지: 모델이 모르는 것을 지어내는 대신 실제 문서를 근거로 답한다.
- 2. 지식 단절 해결: 학습 데이터 이후의 최신 정보도 반영 가능.
- 3. 컨텍스트 절약: 방대한 문서 전체를 넣지 않고 필요한 부분만 가져온다.

NotebookLM이 RAG 원리를 제품화한 대표 사례.

**흐름**

- ① 사용자 질문
- ② 질문을 벡터로 변환(임베딩)
- ③ 벡터DB에서 유사 문서 검색
- ④ 관련 문서 상위 k개 추출
- ⑤ 질문+문서를 LLM에 전달
- ⑥ LLM이 문서 기반으로 답변 생성

**헷갈리는 점**

- **흔한 오해** RAG를 파인튜닝과 혼동
- **차이** RAG = 외부 문서를 검색해서 답변(모델 변경 없음) / 파인튜닝 = 모델 자체를 추가 학습
- **기억법** RAG = 오픈북 시험 / 파인튜닝 = 공부해서 머릿속에 넣기

**카톡으로 이해하기**

> **💬 A** LLM이 잘못된 정보 말하는 거 어떻게 막아?
>
> **🙋 B** 그냥 더 좋은 모델 쓰면 되는 거 아니야?
>
> **💬 A** 그것도 방법이긴 한데 RAG 쓰는 게 더 확실해  
> 답하기 전에 관련 문서 검색해서 그걸 보고 답하게 하는 거야
>
> **🙋 B** 아 찾아보고 말하는 거구나. 근데 파인튜닝이랑 다른 게 뭐야?
>
> **💬 A** RAG는 모델 그대로 두고 외부 문서 검색해서 컨텍스트에 넣는 거고  
> 파인튜닝은 모델 자체를 추가 학습시키는 거야
>
> **🙋 B** 그럼 어떨 때 RAG 써야 해?
>
> **💬 A** 최신 정보가 필요하거나, 회사 내부 문서 기반으로 답해야 할 때  
> RAG는 오픈북 시험, 파인튜닝은 공부해서 머릿속에 넣는 거로 생각해

### Temperature (온도)

`LLM` · Temperature · 추가 2026-10-09

> **LLM 응답의 무작위성(창의성)을 조절하는 파라미터 — 높을수록 창의적, 낮을수록 일관적**

**자세히**

Temperature는 모델이 다음 토큰을 선택할 때 확률 분포를 얼마나 평평하게 만들지 결정하는 값이다. 0에 가까울수록 항상 가장 확률 높은 단어만 선택(일관·정확), 1 이상이면 낮은 확률의 단어도 선택 가능(창의·다양).

**흐름**

- ① 모델이 다음 토큰 확률 분포 계산
- ② Temperature로 분포 조정(높으면 평평, 낮으면 뾰족)
- ③ 조정된 분포에서 토큰 샘플링
- ④ 토큰 선택 → 출력

**헷갈리는 점**

- **흔한 오해** Temperature=0이 가장 좋다고 오해
- **차이** Temperature=0 = 항상 같은 답(정확하지만 단조로움) / 높은 값 = 다양하지만 틀릴 수 있음. 목적에 따라 다름
- **기억법** 코드 생성=낮게(정확) / 소설=높게(창의)

**예시**

- Temperature=0 → '서울의 수도는?' → 항상 '서울' (정해진 답)
- Temperature=1.5 → 같은 질문도 매번 다른 표현, 더 창의적인 답변
- 코드 생성·사실 확인 → Temperature 낮게 (0~0.3)
- 소설·광고 카피·브레인스토밍 → Temperature 높게 (0.8~1.2)

**카톡으로 이해하기**

> **💬 A** LLM에서 Temperature 조절하는 거 뭔 의미야?
>
> **🙋 B** 온도? 뭔가 랜덤성 관련된 거?
>
> **💬 A** 맞아! 출력의 무작위성(창의성) 조절하는 값이야  
> 0에 가까울수록 가장 확률 높은 단어만 선택해서 일관된 답변  
> 1 이상이면 다양하고 창의적인데 가끔 엉뚱한 말 해
>
> **🙋 B** 그럼 언제 높이고 낮춰?
>
> **💬 A** 코드 작성, 데이터 추출 같이 정확성이 중요할 땐 낮게(0.2~0.5)  
> 스토리텔링, 아이디어 브레인스토밍은 높게(0.8~1.0) 써
>
> **🙋 B** 아 같은 질문도 Temperature 따라 답이 달라지겠네
>
> **💬 A** 맞아! Temperature=0이면 매번 같은 답, 높으면 매번 다른 답 나와

**연결 용어** [Top-k](#term-054) · Top-p · LLM · [토큰](#term-003)

### Top-k

`LLM` · Top-k Sampling · 추가 2026-10-09

> **다음 토큰 선택 시 확률 상위 k개 후보 중에서만 고르는 샘플링 방식**

**자세히**

Top-k는 모델이 다음 단어를 고를 때 전체 단어 중 확률이 높은 상위 k개만 후보로 두고 그 안에서 선택하는 방식이다. k=1이면 항상 가장 확률 높은 단어만 선택(greedy), k=50이면 상위 50개 중 랜덤 선택. Temperature와 함께 응답 다양성을 조절한다.

**흐름**

- ① 모델이 전체 어휘 확률 계산
- ② 상위 k개 토큰만 남김
- ③ k개 중에서 Temperature 기반 샘플링
- ④ 토큰 선택

**헷갈리는 점**

- **흔한 오해** Top-k와 Temperature를 같은 것으로 혼동
- **차이** Top-k = 후보 수 제한(몇 개 중 고를지) / Temperature = 선택 확률 분포 조정(얼마나 랜덤하게)
- **기억법** Top-k = 메뉴 3개로 줄이기 / Temperature = 메뉴 중 무엇을 고를지 기분

**예시**

- k=1 → 항상 같은 답 (가장 확률 높은 것만 선택)
- k=50 → 확률 상위 50개 단어 중 랜덤 선택 → 다양한 표현
- Top-k=10, Temperature=0.8 → 상위 10개 후보 중 온도에 따라 확률 조정 후 선택
- Transformer Explainer 사이트에서 직접 k값 바꿔보며 확인 가능

**카톡으로 이해하기**

> **💬 A** Top-k가 뭔지 알아? LLM 설정에 있던데
>
> **🙋 B** 처음 봐
>
> **💬 A** LLM이 다음 단어 선택할 때 확률 높은 상위 k개 후보 중에서만 고르는 설정이야  
> Top-k=5면 5개 후보 중 하나 선택하는 거야
>
> **🙋 B** Temperature랑 다른 거야?
>
> **💬 A** 비슷한 역할이지만 다른 방식이야  
> Temperature는 확률 분포 자체를 조절하고  
> Top-k는 후보 개수를 제한하는 거야
>
> **🙋 B** 아 함께 쓰는 거야?
>
> **💬 A** 응! 보통 같이 조합해서 써. Top-k로 후보 좁히고 Temperature로 선택 다양성 조절해  
> 두 개 다 출력의 다양성을 조절하는 파라미터야

### 레시피 (Recipe)

`LLM` · Recipe (AI context) · 추가 2026-10-09

> **AI에게 원하는 결과를 얻기 위해 미리 설계해둔 프롬프트 구조·템플릿**

**자세히**

AI 맥락에서 레시피는 요리 레시피처럼 '이 재료(입력)를 이 순서로 넣으면 이 결과가 나온다'는 프롬프트 설계 패턴이다. 반복적으로 쓰이는 AI 작업을 표준화한 것으로, 루프 엔지니어링·에이전트 설계의 기본 단위가 된다.

**흐름**

- ① 반복적으로 쓰이는 AI 작업 파악
- ② 입력(재료)·출력(결과)·순서(조리법) 정의
- ③ 프롬프트 템플릿 작성
- ④ 테스트·개선
- ⑤ 재사용 가능한 레시피로 저장

**헷갈리는 점**

- **흔한 오해** 레시피를 단순 프롬프트와 혼동
- **차이** 프롬프트 = 한 번 쓰는 질문 / 레시피 = 반복 사용을 위해 설계된 구조화된 템플릿
- **기억법** 프롬프트 = 즉흥 요리 / 레시피 = 표준화된 요리법

**예시**

- 매주 회의록 요약 레시피: '다음 회의록을 3줄로 요약하고 액션아이템을 추출해줘'
- 코드 리뷰 레시피: '이 코드의 버그·보안 취약점·개선점을 순서대로 알려줘'
- 라이프루프 레시피: 목표 정의 → AI 실행 → 결과 평가 → 개선 반복
- 레시피 = 재사용 가능한 프롬프트 템플릿

**카톡으로 이해하기**

> **💬 A** LLM 쓸 때 레시피라는 말 들었는데 무슨 뜻이야?
>
> **🙋 B** 요리 레시피?
>
> **💬 A** 비유가 맞아! AI에게 어떤 재료(정보)를, 어떤 순서로, 어떤 방식으로 줄지 설계한 것  
> 시스템 프롬프트 + 예시 + 제약 + 출력 형식까지 포함한 전체 설계야
>
> **🙋 B** 그냥 프롬프트 아니야?
>
> **💬 A** 프롬프트보다 더 넓은 개념이야. 프롬프트 하나가 아니라  
> 여러 프롬프트와 컨텍스트, 데이터를 어떻게 조합할지 레시피처럼 정해두는 거야
>
> **🙋 B** 아 한 번 잘 만들면 재사용 가능한 거구나
>
> **💬 A** 맞아! 레시피 = 재현 가능한 AI 활용 설계서야  
> 잘 만든 레시피는 누가 써도 비슷한 결과가 나와

### 컨텍스트

`LLM` · Context · 추가 2026-10-05

**정의** LLM이 응답을 생성할 때 참고하는 대화 전체 내용 또는 배경 정보.

**자세히**

LLM은 현재 질문만 보는 게 아니라, 그 앞의 대화 내용·시스템 지시·첨부 자료 등을 함께 보고 답한다. 이 '함께 보는 전체 정보'가 컨텍스트다.  
컨텍스트 윈도우(Context Window): 모델이 한 번에 처리할 수 있는 최대 토큰 수. Claude 3.7은 200K 토큰, GPT-4o는 128K 토큰 등.  
컨텍스트가 길수록 더 많은 대화·자료를 기억하며 답할 수 있지만, 비용도 늘어나고 처리 속도도 느려진다.  
컨텍스트 엔지니어링: 모델에게 어떤 정보를, 얼마나, 어떤 순서로 넣을지 설계하는 것.

**흐름**

- ① 사용자 질문 입력
- ② 이전 대화 이력 포함
- ③ 시스템 프롬프트 추가
- ④ 전체를 컨텍스트 윈도우에 넣음
- ⑤ LLM이 컨텍스트 전체를 보고 답변 생성

**헷갈리는 점**

- **흔한 오해** 컨텍스트와 프롬프트를 같은 것으로 혼동
- **차이** 프롬프트 = 지금 입력한 질문 / 컨텍스트 = 프롬프트 + 이전 대화 + 시스템 설정 전체
- **기억법** 프롬프트 ⊂ 컨텍스트 — 컨텍스트가 더 큰 개념

**카톡으로 이해하기**

> **💬 A** 챗봇한테 질문하면 이전 대화 내용 알고 대답하던데 어떻게 그래?
>
> **🙋 B** 메모리 같은 거 쓰는 거 아니야?
>
> **💬 A** 그게 컨텍스트야. LLM이 응답 만들 때 지금 질문만 보는 게 아니라  
> 이전 대화 이력, 시스템 설정 같은 걸 다 같이 봐
>
> **🙋 B** 컨텍스트가 프롬프트랑 같은 거야?
>
> **💬 A** 달라! 프롬프트는 지금 네가 입력한 질문이고  
> 컨텍스트는 그 질문 + 이전 대화 + 시스템 설정 전체야  
> 프롬프트가 컨텍스트 안에 포함되는 거지
>
> **🙋 B** 아 그럼 대화 길어질수록 컨텍스트도 커지겠네
>
> **💬 A** 맞아. 근데 모델마다 처리할 수 있는 최대 토큰 수(컨텍스트 윈도우)가 있어서  
> 너무 길면 오래된 내용을 못 보게 돼

### 토큰

`LLM` · Token · 추가 2026-10-05

**정의** LLM이 텍스트를 읽고 처리하는 가장 작은 단위. 글자 수와 다르다.

**자세히**

LLM은 텍스트를 글자 단위가 아니라 '토큰' 단위로 읽는다.  
영어는 단어 하나가 보통 토큰 1개. 한국어는 글자 1~2개가 토큰 1개인 경우가 많아 같은 내용을 영어보다 더 많은 토큰이 필요하다.  
예: '안녕하세요' → 약 5~7토큰 / 'Hello' → 1토큰.  
토큰 수가 중요한 이유: API 비용이 토큰 수로 계산되고, 모델이 한 번에 처리할 수 있는 최대 토큰 수(컨텍스트 윈도우)가 정해져 있기 때문.

**흐름**

- ① 텍스트 입력
- ② 토크나이저가 텍스트를 토큰으로 분리
- ③ 각 토큰을 숫자 ID로 변환
- ④ 모델이 토큰 단위로 처리
- ⑤ 출력 토큰 생성 → 텍스트로 변환

**헷갈리는 점**

- **흔한 오해** 토큰=단어로 오해
- **차이** 토큰 ≠ 단어. '안녕하세요'는 한국어로 3~4토큰, 영어 'hello'는 1토큰
- **기억법** 영어는 1단어≈1토큰, 한국어는 1글자≈1~2토큰 (비싸다)

**카톡으로 이해하기**

> **💬 A** GPT API 쓰는데 왜 비용이 이렇게 많이 나와?
>
> **🙋 B** 요청 많이 한 거 아니야?
>
> **💬 A** 한국어로 했더니 토큰이 너무 많이 나온대. 토큰이 뭔지 알아?
>
> **🙋 B** 단어 아니야?
>
> **💬 A** 아니! LLM이 텍스트 처리하는 최소 단위인데 단어랑 달라  
> 영어는 단어 하나가 보통 토큰 1개인데, 한국어는 글자 1~2개가 토큰 1개야
>
> **🙋 B** 그럼 한국어가 더 비싼 거야?
>
> **💬 A** 맞아. '안녕하세요'가 5~7토큰인데 영어 'Hello'는 1토큰이야  
> API 비용이 토큰 수로 계산되니까 한국어가 더 많이 나오지
>
> **🙋 B** 아 그래서 컨텍스트 윈도우도 토큰 단위구나
>
> **💬 A** 응! 모델이 한 번에 처리할 수 있는 최대 토큰 수가 있어서 거기 넘으면 못 봐
