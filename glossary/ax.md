### AX

`AX` · AI Transformation · 추가 2026-10-05

**정의** AI를 단순 도구로 쓰는 것을 넘어 업무·조직·삶의 방식 자체를 AI 중심으로 바꾸는 변화.

**자세히**

DX(Digital Transformation)의 다음 단계.  
DX가 '디지털화'라면, AX는 'AI가 중심이 되는 재설계'다.  

DX vs AX:  
- DX: 종이 → 디지털, 오프라인 → 온라인 (도구 교체)
- AX: 사람이 하던 판단·반복 업무를 AI가 대신하도록 구조 자체를 바꿈

AX의 핵심:  
- ① 업무 패턴 파악 → ② 반복·병목 구간 발견 → ③ AI로 대체·자동화 설계

AX:IS 동아리 맥락: AI Transformation 시대를 함께 준비하고, 구성원 간 경험을 공유하며 성장하는 AI 자기계발 동아리.

**흐름**

- ① DX(디지털 전환) — 아날로그→디지털
- ② AI 도입 시작 — 단순 자동화
- ③ AX 전환점 — AI가 판단·설계까지
- ④ 업무·조직 구조 자체가 AI 중심으로 재편
- ⑤ 소비자와 생산자로 계층 분화

**헷갈리는 점**

- **흔한 오해** AX와 DX를 같은 것으로 혼동
- **차이** DX = 디지털 도구 도입 / AX = AI가 업무 방식 자체를 바꿈. DX→AX 순서로 발전
- **기억법** DX = 종이→컴퓨터 / AX = 컴퓨터→AI가 판단

**카톡으로 이해하기**

> **💬 A** 요즘 AX 전환이 중요하다는 말 많이 나오던데 DX랑 뭐가 달라?
>
> **🙋 B** DX가 디지털 전환이잖아. AX는 AI 버전?
>
> **💬 A** 맞아! DX가 종이→디지털이었다면 AX는 AI가 업무 방식 자체를 바꾸는 거야  
> 도구 교체가 아니라 구조 재설계야
>
> **🙋 B** 그럼 AI 도구 도입하면 AX야?
>
> **💬 A** 아니, 그건 그냥 AI 도입이야. AX는 사람이 하던 판단·반복 업무를 AI가 대신하도록  
> 구조 자체를 바꾸는 거야. 업무 흐름이 AI 중심으로 재편되는 거지
>
> **🙋 B** DX→AX 순서로 가는 거야?
>
> **💬 A** 맞아. DX가 됐어야 AX도 가능해. DX=컴퓨터로 바꾸기, AX=AI가 판단까지 하기  
> 지금 우리가 AX 전환점에 와 있는 거야

**연결 용어** DX · [루프 엔지니어링](agent.md#term-019) · AI 에이전트 · 라이프루프 · 자동화

### 온보딩

`AX` · Onboarding · 추가 2026-10-16

**정의** 새로운 구성원이나 사용자가 조직·서비스·도구에 빠르게 적응하도록 안내하는 과정

**자세히**

온보딩은 신규 직원이 업무에 적응하는 과정(HR 온보딩)에서 출발했지만, 현재는 앱·서비스의 첫 사용 경험 설계(UX 온보딩), AI 도구 도입 시 구성원 교육(AX 온보딩) 등 다양한 맥락에서 사용된다. AX 맥락에서는 AI 도구를 처음 접하는 사람이 실무에 빠르게 투입될 수 있도록 설계된 교육·가이드 프로세스를 뜻한다.  

\[개발자 맥락\] 개발자들은 주로 3가지 상황에서 온보딩을 사용한다: ① 신규 개발자 팀 합류 시 — 코드베이스·개발환경·컨벤션을 빠르게 익히는 과정 (README, CONTRIBUTING.md, 로컬 세팅 가이드 등이 온보딩 자료). ② API·SDK 제공 시 — 외부 개발자가 자사 API를 처음 연동할 때의 경험 설계 (Quick Start, 샘플 코드, Sandbox 환경 제공). ③ 서비스 사용자 첫 경험 — 앱 첫 실행 시 튜토리얼·가이드 화면 (UX 온보딩 플로우). 개발자 커뮤니티에서는 '온보딩이 잘 된 프로젝트'가 기여자를 더 많이 모은다는 인식이 강하다.

**흐름**

- 흐름: 도입 결정 → 온보딩 설계 → 실습 교육 → 현업 적용 → 피드백

**헷갈리는 점**

- 헷갈리는 포인트: 온보딩은 단순 교육이 아니다 — 교육(1회성) vs 온보딩(지속적 적응 설계). 온보딩이 잘 되면 도구 도입 실패율이 크게 낮아진다. 개발자 관점 추가: API 온보딩(외부 개발자용) vs 팀 온보딩(내부 신규 개발자용) — 대상이 다르므로 자료 설계가 완전히 달라진다.

**카톡으로 이해하기**

> **💬 A** 야 우리 팀에 신입 들어왔는데 온보딩 자료 만들어야 해
>
> **🙋 B** 온보딩이 뭔데?
>
> **💬 A** 새로 합류한 사람이 빨리 적응하게 도와주는 과정이야  
> 개발팀이면 로컬 환경 세팅법, 코드 컨벤션, 배포 방법 같은 거 정리해두는 거
>
> **🙋 B** 아 그거 README에 써두는 거 아니야?
>
> **💬 A** README는 프로젝트 소개고, 온보딩은 "첫날 뭐부터 해야 하는지" 플로우야  
> 예를 들면: 1. 레포 클론 → 2. .env 설정 → 3. DB 마이그레이션 → 4. 로컬 서버 실행
>
> **🙋 B** 아 그냥 체크리스트네
>
> **💬 A** 맞아! 근데 API 서비스라면 외부 개발자 온보딩도 따로 있어  
> Quick Start 문서, 샘플 코드, Sandbox 환경 이런 게 다 온보딩이야
>
> **🙋 B** 그럼 AI 도구 도입할 때도 온보딩이 있겠네
>
> **💬 A** 당연하지. ChatGPT 도입하면 "어떻게 써요?"부터 막히잖아  
> 그 과정 설계하는 게 AX 온보딩이야

### 워크플로

`AX` · Workflow · 추가 2026-10-05

**정의** 어떤 목표를 달성하기 위해 정해진 순서대로 실행되는 작업들의 흐름.

**자세히**

일이 처리되는 순서와 흐름을 구조화한 것.  
사람이 하던 단계별 작업을 명확히 정의해야 자동화할 수 있다.  

예시:  
- 콘텐츠 제작 워크플로: 아이디어 → 초안 작성 → 검토 → 편집 → 발행
- 야간질문봇 워크플로: 질문 수신 → 분류 → 처리(검색/요약/설계) → 결과 전송
- 채용 워크플로: 지원서 접수 → 서류 검토 → 면접 → 합격 통보

AI 자동화 맥락:  
워크플로를 먼저 명확히 그려야 AI로 어느 단계를 대체할 수 있는지 보인다. AX의 핵심은 '업무 패턴화 → 워크플로 정의 → AI 자동화 설계' 순서.  

도구: n8n, Make(Integromat), Zapier 등이 워크플로 자동화 플랫폼.

**흐름**

- ① 목표·결과물 정의
- ② 필요한 작업 목록 나열
- ③ 순서·의존관계 설정
- ④ 각 단계 실행(사람·AI·자동화)
- ⑤ 결과 확인 및 다음 단계 트리거

**헷갈리는 점**

- **흔한 오해** 워크플로와 프로세스 혼동
- **차이** 프로세스 = 작업의 흐름(개념) / 워크플로 = 실제 실행 가능한 구체적 단계 정의
- **기억법** 워크플로 = 요리 레시피 (재료·순서·시간 구체적으로 명시)

**카톡으로 이해하기**

> **💬 A** 업무 자동화한다는 게 구체적으로 어떻게 하는 거야?
>
> **🙋 B** 그냥 매크로 같은 거 쓰는 거 아니야?
>
> **💬 A** 워크플로 만드는 거야. 반복 업무를 단계별로 정의해서  
> 특정 조건에서 자동으로 실행되게 연결하는 거지
>
> **🙋 B** 단계별로 연결한다는 게 어떤 거야?
>
> **💬 A** 예를 들어 '구글폼 응답 수신 → AI로 요약 → 슬랙 알림 발송' 이런 흐름  
> 각 단계가 이어지는 걸 워크플로라고 해
>
> **🙋 B** 아 일의 흐름을 설계하는 거네
>
> **💬 A** 맞아. n8n 같은 도구로 시각적으로 블록 연결해서 만들 수 있어  
> 워크플로 = 자동화된 업무 흐름 설계라고 기억해
